## 2. 输入规格（obs 向量，821 维 float32，Box[-1,1]）

**一 agent 一行**。C 内核逐段打包（`drive.h:6253-6260` 打包顺序），Python 侧按同序切片（`torch.py:156-200`）：

| # | 段 | 维度 | 语义（归一化到 ≈[-1,1]，`write_*_obs` 系列逐特征写） |
|---|---|---|---|
| 1 | ego | 11 | 有符号速度/60mps（`obs_norm_speed_mps=60.0`，`drive.py:146`；**勘误 2026-11-14**：原文档误写 /15mps）、宽/长（含 eval 感知余量）/车规、转向角/限、纵/横加速度/限、车道横向距离（归一化常数待核）、车道航向误差/π、当前车道限速/60mps、停车秒数（capped）、车道曲率 |
| 2 | reward 条件 | 19 | 19 个奖励系数的当前取值（goal_radius…progress + 动态条件 4 项，`constants.h:351-369` 索引表）——策略被显式条件化于奖励形态 |
| 3 | goals | 3×3 | 目标点（ego 系 x,y,z），滚动窗口 `num_goals=3` |
| 4 | partners | 20×11 | 近邻车/人/骑（按距离取 20 槽）：类型、相对位姿、尺寸、相对速度 2 列（`obs_partner_relative_velocity` 开）等 |
| 5 | lanes | 35×10 | 前方路径车道段（70 槽抽稀保形到 35）：相对折线点 + 限速列（`obs_lane_speed_limit` 开） |
| 6 | boundaries | 30×6 | 车道边界（50 槽保形到 30） |
| 7 | traffic controls | 4×7 | 灯/停牌/让行：几何 5 列 + **类别/状态两列整数索引**（喂 one-hot 4+5 类；这两列**不是归一化值**，随机张量做 dummy 会炸 one_hot——导出脚本因此用真实 env obs） |
| 8 | valid counts | 4 | lanes/boundaries/partners/traffic 的有效槽计数（masked max-pool 的掩码源） |

**无输入归一化层**：PufferLib 的 obs_stats 只作监控统计（`pufferl.py:323-330`），eval 前向吃 C 内核产出的裸 obs——ONNX 图两侧均不需要预处理。惰性槽为零填充，由 valid counts + masked max-pool 处理（`torch.py:_encode_and_pool`）。

**无车道哨兵勘误（2026-11-14）**：ego 列 8（限速列）在无当前车道时盘上实值为 **−1/60 ≈ −0.0167**（写入前 −1.0f 先除 60，`drive.h:5777-5779`），非原文档所写 −1。同理列 0 哨兵可由 `col8 > 0` 判定有车道。

## 3. 输出规格

| 输出 | 形状 | 语义 |
|---|---|---|
| `action_logits` | [B, 12] | 离散动作 logits。**k = long_idx×3 + lat_idx**，物理表：long ∈ {-15, -4, 0, +4} m/s³（jerk），lat ∈ {-4, 0, +4} m/s³（`constants.h:133-136`，`torch.py` action_table） |
| `value` | [B, 1] | critic V(s)（部署可弃） |

**解码两种语义（部署必选一）**：
- `argmax(logits)` → 贪心离散动作
- **eval 一致语义（默认 `eval.action_selection: mean`）**：`softmax(logits) @ action_table_physical` → 物理域 (jerk_long, jerk_lat) → 各自除以 (15, 4) 归一到 Box[-1,1] 喂动力学（`torch.py:discrete_probs_to_continuous_mean`；`pufferl.py:2420-2422` 离散策略+连续 env 分支）。**复现本仓评测分数必须用这条路径**

动作经 jerk 动力学积分（`DYNAMICS_MODEL_JERK`），dt=0.0667s（15Hz），episode 500 步 ≈ 33.3s。

## 4. 网络架构（`torch.py`）

```
obs[821] ─┬─ ego_encoder(11→256, LN+relu, 2 层 MLP) ──────────────┐
          ├─ lane_encoder(10→256)   ── 35 槽 masked max-pool ──┤
          ├─ boundary_encoder(6→256) ── 30 槽 masked max-pool ──┤   concat(1280)
          ├─ partner_encoder(11→256) ── 20 槽 masked max-pool ──┤ → backbone MLP 1024×3 (gelu)
          ├─ traffic_encoder(7→12† →128) ── 4 槽 masked max-pool┤       ├─ actor_head 256×1 + Linear→12
          └─ context_encoder(28‡→128)（reward 19 + goals 9）────┘       └─ critic_head 256×1 + Linear→1
```
† 7 = 5 连续 + type/state one-hot(4+5) 后 14→128；‡ 19+9=28。双 backbone（actor/critic 各一份同构，`shared_network: false`）；`fp32_heads: true`（bf16 训练时头走 fp32，导出/推理全 fp32 无差）。masked max-pool：`encode(slots) → 无效槽填 dtype 最小值 → max → 空槽置零`。

## 5. ONNX 导出（`scripts/export_onnx.py`，本文实证）

```bash
PYTHONPATH=$PWD .venv/bin/python scripts/export_onnx.py \
  --run-dir artifacts/t3-R4x/ckpt/R_ent5_off23 \
  --ckpt   artifacts/t3-R4x/ckpt/R_ent5_off23/models/model_puffer_drive_007424.pt \
  --out    artifacts/onnx/t3-R4x-champ.onnx
# 16× 新冠军（lab42 sshd 恢复后拉权重到 artifacts/t3-f16-16x-champ/ 同命令换路径）
```

保真要点：
- **config 驱动实例化**：与 `pufferl.load_policy` 同构——用 ckpt 自带 config.yaml 建 Drive env（定 obs/action 维）+ 建策略 + `load_state_dict(strict=True)`，槽布局永不错位
- **fused_slot_encoder 关闭**：Triton 核不可 trace；dense masked 路径**数学等价**（同一 `_encode_and_pool` 的非融合分支）
- **dummy = 真实 env obs**（交通灯类别列是整数索引，随机张量非法输入）
- 导出后三重验证：`onnx.checker` ✓ · onnxruntime 数值对拍 **max|Δ|=8.6e-6 < 1e-4** ✓ · sidecar JSON 记录 obs_dim/action_classes/参数量

实测产物：两个冠军各导出一份（fp32；主文件 ~378KB 图结构 + `.onnx.data` ~30MB 权重外置，ort 自动加载），batch 维动态，输入名 `observations`，输出名 `action_logits`/`value`；ORT 对拍 4× 冠军 max|Δ|=8.6e-6、16× 冠军 max|Δ|=1.1e-5。依赖：`onnx/onnxruntime/onnxscript`（已装 `.venv`，走代理 pip）。

## 6. 测试数据来源与构造

**来源 = 仓内 CARLA Town 地图 bin**（`pufferlib/resources/drive/binaries/carla/`，8 城 OpenDRIVE 转换，含车道图）。**无外部数据依赖**——场景全部程序化生成（Terra 哲学：「少量地图，无限场景」）。

**构造（`benchmark.yaml` `carla_fast` 条目 + gigaflow 内核）**：
1. 种子 42 固定 → 场景流 `(map_idx, scenario_seed)` 确定：场景在 8 城轮转，`num_scenarios=N` 取流前 N——**同一 benchmark 下不同 N 是前缀关系**（本仓 200/400 场景 eval 直接可比的根据）
2. 每场景：从可行驶车道网格按 seed 采样 ego+伙伴出生位姿（`spawn` 从 drivable 网格，`drive.h` reset 路径），随机路由目标（`goal_source=route`，30m 间距滚动窗口）
3. 交通灯**程序化配时**（训练随机时长 + 20% 关闭/常绿；eval 默认 10s 绿/3s 黄/2s 红，`constants.h:302-308`）
4. **两面**：clean = `hazard_enable=false, cosim_partner_slots=0`（显式 CLI 压回训练配置残留）；mix = hazard 四开（parked/clusters/cones/walkers）+ 静态槽容量 44——恶劣长尾面
5. 评测 env 覆盖：`eval_mode`（`collision_behavior=stop` 等：碰撞/出界/闯灯即停该 agent）+ 评测奖励档（`benchmark.yaml` env 段 19 项钉死，含 `reward_randomization=false`）

## 7. 测试方法（`pufferl eval`）

```bash
PYTHONPATH=$PWD .venv/bin/python -m pufferlib.pufferl eval puffer_drive carla_fast \
  load_model_path=<ckpt.pt> eval.num_scenarios=400 \
  [mix 面：--mix-face 经 t3_eval_ckpt.py，或 CLI env.hazard_enable=true + 槽容量] \
  eval.output_dir_name=<abs out> [train.device=cpu train.compile=false]
```
- 多进程向量化 rollout（worker = min(num_envs, 线程数)），逐 episode 收内核日志行 → `episode_metrics.csv`（逐行=逐 episode 聚合）→ 均值入 `evaluation_summary.json`
- 动作选择 = §3 的 mean 语义；obs 裸喂（无归一化）
- 批量对照（多 ckpt 同面同场景数）走 `scripts/t3_eval_ckpt.py`（自动双面 + summary.json/index.html）

## 8. 指标计算逻辑（内核 `drive.h add_log`，`compute_eval_metrics` 路径）

**逐 episode、逐 agent 聚合**（盲/幻影伙伴不计），episode = 500 步：

| 指标 | 计算 |
|---|---|
| `episode_return` | Σ reward（评测奖励档：progress 区间 + collision 3.0 + goal 1.0 + comfort/velocity/lane 系小项 − timestep 等） |
| `collision_rate` 等 | 计数制：该 episode 内 offroad/碰撞/闯灯/闯停牌**次数**求和（≥1 即事故 episode；报告值 = 跨 episode 均值） |
| `dnf_rate` | **零违规且零 goal** 的 agent 计数（「无借口没跑完」——排除因事故停下的） |
| `score` | 1/agent 当且仅当集齐全部 goals 且未 removed/stopped |
| `num_goals_reached` | 达成 goal 计数（理论 3） |
| `avg_speed_per_agent` | 每 timestep 归一均速 |
| `progress_ratio` | 行驶距离 /（参考速度×时长），下限 1.0 |
| `at_fault_collision_rate` | 责任归属碰撞（对方为共享策略伙伴时计 0.5 份额等，`is_shared_policy_collision`） |
| `spawn_reject_*` | 出生拒绝原因计数（spawn 公平性卫生指标） |
| 舒适/车道系 | `comfort_violation_count/timestep`、`lane_center_rate` 等每步归一 |

**报告聚合**：`_build_eval_report`（`evaluation_utils.py:370-395`）对 CSV 数值列取跨 episode 均值（`reduce_environment_metrics`），即本仓所有表格里的 `ret/coll/dnf` 口径。
